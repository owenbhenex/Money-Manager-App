# BUG-001: API routes return HTTP 500 + leak JSON parser internals on malformed input

Severity: Minor        Priority: P2
Status: New            Found in: b76af41 (Phase 2)          Date: 2026-09-28
Environment: http://localhost:3100, Node v22.23.1, Next.js 16.3.6 Turbopack
Related test case: TC-BANK-007

## Steps to reproduce
1. Start dev server (`npm run dev`)
2. Send malformed JSON to ANY POST route:
   `curl -X POST http://localhost:3100/api/bank/connect -H "Content-Type: application/json" -d '{invalid'`
3. Repeat for `/api/subscriptions/detect` and `/api/copilot/chat`

## Expected result
HTTP 400 with a generic error message (e.g. "Invalid JSON body"). No parser internals exposed.

## Actual result
HTTP 500 with the raw V8 JSON parser message leaked into the response:
`{"error":"Expected property name or '}' in JSON at position 1 (line 1 column 2)"}`

## Evidence
- /api/bank/connect  -> 500, leaks parser message
- /api/subscriptions/detect -> 500, leaks parser message
- /api/copilot/chat -> 500, leaks parser message (Phase 1 code, same pattern)

## Frequency: always (3 of 3 routes)
Workaround: none needed for normal use; clients send valid JSON.
Scope/impact: all POST API routes. Information disclosure (parser state) but no secrets.
Suspected cause (hypothesis only): every route does `await req.json()` directly in the try block with no validation; a SyntaxError from bad JSON surfaces as a 500 with the raw error.message. Fix = try/catch around the `.json()` call returning a clean 400, e.g. `try { body = await req.json() } catch { return NextResponse.json({error:'Invalid JSON'}, {status:400}) }`.
